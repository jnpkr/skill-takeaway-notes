# Takeaway notes

Write the note in **telegraphic** style: fragments, symbols (→, =, ~, ≤) and bullets. Every fact survives and the connecting prose goes.

## Structure
1. Title, then one line of context: date, client or subject, and the starting situation.
2. **Bottom line**: the answer or decision, 2–4 bullets.
3. Topic sections, ordered as a reader would act on them (what it is → current state → options → cost → steps → terms, risk, retention).
4. Tables for any comparison across tiers or options.
5. **Open items** as `- [ ]` checkboxes: unresolved questions, verifications and next actions.
6. **Sources** with raw URLs, so links survive pasting anywhere.

## What to keep
- Every number, limit, price, date, product name, menu path and setting name.
- Caveats attached to the fact they qualify, e.g. "(partner source)", "(unverified)" or "(applies today too)".
- The final state only: when the conversation corrected something, write the corrected version.
- Findings that rule something out, written as a fact, e.g. "admin switch = Gemini Enterprise, n/a to gemini.google.com".

## Done when
Every fact, figure, caveat and open question from the conversation appears once, and each line reads as content, not as narration of how it was found.

## Output
Save a `.md` file to the outputs folder and present it. Reply with one line: what the note covers and where the open items are.
